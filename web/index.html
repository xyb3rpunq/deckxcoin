01

The thesis

Two whitepapers, one chain, and the specific reason nobody merged them properly before.

Bitcoin (Nakamoto, 2008) solved ordering without identity. Ethereum (Buterin, 2013; Wood, 2014) solved arbitrary state transition. Both solutions are correct. The combination is where things have historically gone wrong, and the failure is always the same shape: whoever bolts a contract VM onto a UTXO chain ends up either (a) abandoning UTXOs for accounts, which forfeits parallel validation and makes payment channels awkward, or (b) keeping UTXOs and letting contracts custody value, which recreates the single-pot honeypot that every large Ethereum exploit has drained.

DeckxCoin takes a third route. Contracts never hold money. There is no balance field on a contract account — look at ContractAccount in src/state.ts and you will not find one. Value sent to a contract address stays an ordinary UTXO. The only difference is what unlocks it: not a signature, but the contract answering "may this specific spend proceed?"

There is no pot to drain — only individual outputs whose release a contract may approve or refuse. Reentrancy is not mitigated here; it is absent, because there is no cross-contract call opcode and nothing for a callback to re-enter.

Where Bitcoin actually stands in 2026 — and why this matters here

Bitcoin's last consensus change was Taproot, November 2021. That is the longest quiet stretch in its history. The 2026 debate is about covenants — letting an output constrain how it may be spent:

  • BIP-119 (OP_CHECKTEMPLATEVERIFY) — deployment parameters propose a start of 30 Mar 2026 and a minimum activation height in May 2027, with a 90 % miner-signalling threshold. Signalling has been effectively zero, so this attempt is unlikely to activate.
  • BIP-348 (OP_CHECKSIGFROMSTACK) — CTV + CSFS has emerged as the frontrunner pairing among core developers for a next soft fork.
  • BIP-347 (OP_CAT) — specification reached "Complete" status on 1 Mar 2026 and has ~74 000 test transactions on Bitcoin Inquisition's signet, but remains contested.

The honest summary: none of these is likely to change Bitcoin during 2026. DeckxCoin's covenant model is what those proposals are trying to reach — it just gets there by designing the rule in from genesis rather than retrofitting it under a soft fork's backwards-compatibility constraints.

Sources: Bitcoin Optech — Covenants · Spark — CTV / APO / OP_CAT compared · AMINA — Bitcoin fork, August 2026

03

What we took from Ethereum — and what we refused

A contract VM is a liability surface. Every feature below was a decision, not a default.

Kept

256-bit words
Not because 256 bits is a sensible machine word — it isn't — but because a hash digest becomes a single stack item, and every meaningful contract manipulates digests.
Gas metering
Charged before each opcode, so out-of-gas can never leave a half-applied write. Out-of-gas still consumes the full limit; that is what makes spam expensive.
Persistent storage + state root
Every block header commits a stateRoot over the whole world state, so a light client can be handed a storage value and verify it.
REVERT semantics
All writes discarded, gas already spent stays spent.
EIP-170 code size limit
24 576 bytes. Same reasoning: bound worst-case validation cost.
EIP-3529 refund cap
Storage-clearing refunds capped at 20 % of gas used, so refunds can never be farmed into gas tokens.
CREATE-style addresses
Deterministic from (deployer, nonce), so a deployer knows the address before mining.

Refused

CALL / DELEGATECALL
Cross-contract reentrancy is the single largest source of value lost on Ethereum. DeckxCoin contracts are leaves. Removing the opcode removes the bug class, instead of asking every developer to remember a mutex.
Contract balances
No balance field. Contracts authorise spends of UTXOs; they never custody them.
SELFDESTRUCT
State that can vanish underneath a pending transaction is a footgun with no remaining legitimate use.
Unbounded BALANCE probing
A contract may read only its own balance. Probing arbitrary accounts is a privacy leak with no use case here.
Hexary Merkle-Patricia trie
Replaced with a sorted binary trie: same canonical root, same O(log n) proofs, about a tenth of the code — and therefore a tenth of the surface for a state-root divergence bug.
Keccak
One hash family for the whole chain (SHA-256, domain-tagged BIP-340 style). Fewer primitives, fewer ways to get domain separation wrong.

Where Ethereum actually stands in 2026

  • Fusaka activated December 2025, shipping PeerDAS to scale rollup data availability.
  • Glamsterdam is the next hard fork, targeting H2 2026. Its two headline proposals are EIP-7732 (enshrined proposer-builder separation) and EIP-7928 (block-level access lists), alongside EIP-7778, 7843, 7976, 7981 and 8024.
  • The fork reached its final devnet stage with ten EIPs locked in and a path cleared toward a 200 M gas-limit floor. Ethereum Foundation contributors have said Glamsterdam is proving trickier and slower than Fusaka, so a slip is possible.

Note what block-level access lists are for: telling validators up front which state a block touches, so execution can be parallelised. That is a property a UTXO chain has by construction — inputs name their own history. DeckxCoin does not need EIP-7928 because it never gave up the thing EIP-7928 is trying to recover.

Sources: ethereum.org — Glamsterdam · EF blog — Checkpoint #8, Jan 2026 · The Defiant — final devnet, 200 M gas target

04

The fusion: covenant outputs

Bitcoin's outputs. Ethereum's authoriser. One rule, twelve lines of consensus code.

An address whose bech32m version byte is 1 is a contract address. An output paid to one is a normal UTXO in every respect except its unlocking condition:

Consensus rule — covenant spend

  1. The spending transaction must be of kind call.
  2. Its contract.target must equal the address that locked the output.
  3. The contract must execute successfully and return a non-zero first word (approved).
  4. If the contract returns a second word, some output of the transaction must pay that address.

Rule 4 is the one that is easy to miss. Without it, an approval is a bearer token: anyone who sees a valid approved call can rebroadcast it with the outputs pointing at themselves. test/covenant.test.ts asserts exactly this attack fails.

The reference contract: REKT Vault

A time-locked release, written in DVM assembly. It is the contract deployed in the live scenario below — the same bytecode whose storage you can read in the explorer.

src/scenario.ts · rektVaultCode()
asm(
  // First execution only: seed the terms. slot 0 is zero exactly once.
  0n, OP.SLOAD, OP.ISZERO, '@init', OP.JUMPI,
  '@check', OP.JUMP,

  'init:',
  BigInt(unlockHeight), 0n, OP.SSTORE,       // slot 0 ← unlock height
  addressWord(beneficiary), 1n, OP.SSTORE,   // slot 1 ← beneficiary

  'check:',
  2n, OP.SLOAD, 1n, OP.ADD, 2n, OP.SSTORE,   // slot 2 ← attempts + 1

  // approved = NOT(unlockHeight > NUMBER)  ⇔  NUMBER >= unlockHeight
  OP.NUMBER, 0n, OP.SLOAD, OP.GT, OP.ISZERO,

  OP.DUP1, 1n, REKT_TOPIC, OP.LOG,           // emit the decision
  1n, OP.SLOAD,                              // push the beneficiary
  2n, OP.RETURN,                             // → [approved, beneficiary]
)

Compare this with what Bitcoin would need. A vault with the same semantics requires OP_CTV (unactivated), or OP_CAT plus signature gymnastics (unactivated), or a trusted co-signer. Ethereum can express it in Solidity in ten lines — but the contract must hold the ether, which means a bug in it drains everyone's deposit at once. Here, a bug in the vault affects the vault's own outputs and nothing else.

Monetary policy

21,000,000 DECKX. Halving every 365 days. The initial subsidy is derived, not chosen.

Bitcoin halves every 210,000 blocks — roughly four years. DeckxCoin halves every 365 days, which at 600-second spacing is exactly 365 × 24 × 6 = 52,560 blocks.

Fixing both the cap and the interval leaves no freedom in the initial subsidy. A geometric halving series sums to 2 × interval × subsidy, so the constant falls out of the constraint:

src/block.ts
MAX_SUPPLY       = 21_000_000 × 100_000_000        = 2,100,000,000,000,000 zaps
HALVING_INTERVAL = 365 × 24 × 6                    = 52,560 blocks
INITIAL_SUBSIDY  = MAX_SUPPLY / (2 × HALVING_INTERVAL)
                 = 19,977,168,949 zaps             = 199.77168949 DECKX

// Summing all 64 eras:  2,099,999,998,972,800 zaps = 20,999,999.99 DECKX
// Headroom under the cap: 1,027,200 zaps = 0.0102720 DECKX

That constant is ugly, and it is ugly on purpose. Rounding up to a tidy 200 DECKX would issue 21,024,000 DECKX — over the cap — and then require a special-cased final era to clip the excess. A discontinuity in the issuance curve is a consensus edge case that gets exercised exactly once, decades after anyone last thought about it. The derived constant lands under the cap on its own, exactly as Bitcoin's does.

The cap is additionally enforced as a consensus rule rather than left as a property of the arithmetic. The check should never fire; that is precisely why it is cheap insurance.

The cost of a one-year halving, stated plainly. This schedule front-loads issuance hard: roughly 50 % of all DECKX exists after one year and 99.9 % within a decade. Bitcoin reaches the equivalent point around 2140. The security budget therefore shifts from subsidy-funded to fee-funded about an order of magnitude faster, and any real deployment needs a working fee market within a few years, not a few decades. This is a genuine trade-off, not a free upgrade.

06

The standard covenant library

Five contracts covering the patterns account-model chains implement as custodial token contracts — and implementing them as spending conditions instead.

The structural difference matters. On Ethereum a vesting contract holds everyone's tokens, so a bug in it drains all of them. Here a vesting covenant guards one output belonging to one beneficiary. The blast radius of a bug is the output, not the protocol.

Every contract below publishes its storage layout, its exact approval conditions, and its caveats. A test enforces that each one declares at least two caveats — a contract whose author has found none has not looked hard enough.

Authoring covenants

Contracts are assembled from named fragments in src/contracts/lib.ts rather than written as raw opcodes — the stack order of SSTORE alone (value, then key) caused more bugs during this project than every cryptographic primitive combined. Loops over owners are unrolled at build time by JavaScript, so the deployed bytecode contains no loop and burns no gas running one.

Determinism, stated precisely

Execution is a pure function of (code, calldata, context, storage). The context carries only blockNumber, blockTime, caller, callValue and a balance lookup — all of which are fixed once the block is fixed. Two nodes replaying the same block always reach the same state root. There is no source of entropy for a contract to read, which also means there is no on-chain randomness; any contract needing it must take it from calldata and live with the consequences.

Volt — the Lightning-shaped layer

Two on-chain transactions per channel. Everything between them is off-chain, atomic, and private.

Volt is a faithful implementation of the Poon–Dryja construction, mapped onto DeckxCoin's script types. The security argument is asymmetry: whoever broadcasts a channel state is the one who waits, and whoever broadcasts an old one loses everything.

Where Lightning actually stands in 2026

  • Taproot channels are live — Phoenix shipped full support, cutting roughly 20 % off open/close on-chain fees and making channel transactions indistinguishable from single-sig spends.
  • Splicing was merged into the BOLT specification and enabled by default in Core Lightning during 2026; Eclair has cross-implementation interop and LDK moved splice-out from experimental bit 155 to production bit 63.
  • BOLT 12 offers merged into the spec in late 2024; Core Lightning, LDK and Eclair support them natively, though LND — still the most deployed implementation — lacks native Offers support as of mid-2026.
  • PTLCs are underway: adaptor signatures instead of hashes, so the same payment hash no longer identifies one payment across every hop.

Volt sits deliberately at the 2018–2024 feature line — the parts that are settled and auditable — with the PTLC upgrade scaffolded rather than half-built.

Sources: Spark — State of Lightning 2026 · Voltage — Taproot and Lightning · From HTLCs to PTLCs

Why the onion is 1366 bytes no matter what

A one-hop route and a twenty-hop route produce byte-identical packet sizes. Each hop shifts the routing block and appends fresh keystream to the tail; without the sender's pre-computed filler, that tail would decrypt to zeroes and instantly reveal how many hops remain. The filler makes the tail indistinguishable from ciphertext at every position in the route. test/onion.test.ts asserts the size set has exactly one element across routes of 1, 2, 5, 12 and 20 hops.

The node

P2P over real TCP, SQLite persistence, and reorganisation with undo records. This is the part that turns a library into a network.

wire protocolframed
persistenceSQLite
rpc methods21
new deps0

The chain shipped as a library first, and a library is not a network. Two miners find a block at the same height within hours of any real deployment, and an append-only chain has no answer for that. Four things had to exist before testnet meant anything: durability, a block index, undo records, and a wire protocol.

Persistence uses node:sqlite, which ships with Node. The full node therefore adds zero dependencies to the three the chain already had.

ConcernApproach
Durability WAL-mode SQLite. Every block applies inside a transaction — a half-written block is the single failure that silently forks a node off the network.
Reorgs Each block writes an undo record, so disconnecting restores the exact prior state in O(inputs) rather than replaying from genesis. After undo, the restored state root is checked against the parent's committed root — if they disagree the node halts instead of continuing on an unknown chain.
Fork choice Most accumulated work, not longest. Losing branches are retained: a branch that loses today can win tomorrow, and a node that discarded it would have to re-download.
Failed reorgs If any block on a new branch fails to connect, the entire move is rolled back and the original tip restored. A failed reorg must never leave a node half-applied.
Depth limit A reorg deeper than the undo window is refused, not attempted with missing data.
Mempool Transactions from disconnected blocks return to the pool; those in connected blocks leave it; the remainder is revalidated against the new tip. Skipping this is how a node ends up relaying transactions a reorg already invalidated.
Orphans Blocks arriving before their parent are held — bounded to 100, because an unbounded orphan pool is a free memory-exhaustion attack — and connected once the gap fills.
Wire encryption Ephemeral ECDH, then ChaCha20-Poly1305 per frame. Plaintext frames let anyone on the path see which transactions originate at which node — a deanonymisation oracle given away for free. The length prefix is encrypted too, because message sizes are a fingerprint: 1366 bytes is an onion, 24 bytes is a handshake acknowledgement. Keys ratchet forward every 4096 frames.
What encryption does not fix No ElligatorSwift, so the handshake bytes stay recognisable as curve points to traffic classification — that defends confidentiality, not censorship-resistance. And the ephemeral key is bound to no long-term identity, so an active attacker already on the path is not stopped. Bitcoin has the same property.
Ban scoring 1 point for version skew, 10 for a protocol violation, 100 for an invalid block or a framing error. A peer that is merely behind is never banned; banning honest nodes for being out of date is how a network partitions itself.

Convergence is measured on the state root, not the tip hash

Two nodes can agree on which block is the tip while disagreeing about the UTXO set underneath it — and that node forks off the network three blocks later, for reasons that look unrelated. Every convergence assertion in test/network.test.ts compares stateRoot(), and the testnet's status line does the same.

Volt watchtower

The penalty transaction closes the theft loophole in payment channels — but only if somebody broadcasts it. Until the watchtower existed, a channel was safe only while its owner was online, and "mostly online" is not a security property.

A naive tower is handed the channel list and the revocation secrets, and thereby learns the user's entire payment graph — a worse leak than the risk it removes. Instead each update registers an encrypted blob keyed by a hint: the first 16 bytes of the commitment txid are the lookup key, the last 16 bytes are the decryption key. The tower stores the first half and learns nothing — it cannot read the blob, or even tell which channel it belongs to. When the commitment appears on-chain the tower sees the full txid, derives the key from the half it now knows, decrypts, and broadcasts.
